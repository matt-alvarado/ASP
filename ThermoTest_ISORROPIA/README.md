# ASP ThermoTest vs ISORROPIA II

Compares ASP's bulk inorganic thermodynamics (ThermoTest run mode) with ISORROPIA II for seven cases at nine
temperatures (273.15–313.15 K every 5 K), RH 0.20–0.90 in steps of 0.02. Written for the review of
`common_asp` `asp_v2.2.2` (patches 26–33) before merging to master.

## Cases (`cases.py`, inputs in µg m⁻³)

| Case | Input | Purpose |
|---|---|---|
| Urban | NH3 3.4, H2SO4 9.143, HNO3 1.953 | ISORROPIA test case (default `AerosolModes.in`) |
| Marine | NH3 0.02, H2SO4 0.510, HNO3 0.163, NaCl 5.01, HCl 0.002 | ISORROPIA test case |
| Remote | NH3 4.25, H2SO4 11.270, HNO3 0.145 | ISORROPIA test case |
| Smoke_K | KCl 18.12, NH4Cl 31.45, NH4NO3 9.28, (NH4)2SO4 12.48 | potassium; Timbavati sample 3, bulk neutralized |
| Recip_K_NH4 | K2SO4 4.0, NH4NO3 4.0 | near-singular: K/NH4/NO3/SO4 reciprocal salt pair |
| Letovicite | NH3 2.555, H2SO4 9.808 (NH4:SO4 = 1.5) | near-singular: (NH4)3H(SO4)2 = (NH4)2SO4 + NH4HSO4 |
| Recip_Na_NH4 | NaCl 3.0, NH4NO3 4.0 | near-singular: Na/NH4/Cl/NO3 reciprocal salt pair |

## Requirements

- An ASP build from `common_asp` `asp_v2.2.2` (patch 33 or later for the upward scan).
- ISORROPIA II 2.3 from https://github.com/EPFL-LAPI/ISORROPIA-II. It is licensed for academic, non-commercial use and
  is **not** included here; `build_iso.sh` compiles it with `iso_driver.f` (our driver: reads the eight totals in
  mol m⁻³, temperature and the metastable flag, and prints gas, liquid and solid results for RH 0.90 → 0.20).
- Python 3 with numpy, pandas, matplotlib, openpyxl; gfortran.

Paths and labels come from `config.py` (environment variables `THERMO_WORK`, `THERMO_OUT`, `ASP_DECKS`, `ISO_EXE`,
`TAG_DOWN`, `TAG_UP`, `ASP_LABEL`); by default
run directories go to `work/`, plots and the workbook to `results/`, and the deck is `../InorganicInputDecks`.

## Steps

```bash
./build_iso.sh /path/to/ISORROPIA-II            # isobuild/iso
python3 run_iso.py                               # ISORROPIA stable + metastable, all cases and temperatures

# ASP run directories (copies of the default deck: one bulk mode, ThermoTest on, coagulation off,
# T set per run, initial NH3/HNO3/HCl/H2SO4 gas zero)
for tag in down up worst base; do python3 mkcase.py $tag; done
./run_asp.sh down  /path/to/asp_v2.2.2/asp_binary                       # RH scanned down 0.90 -> 0.20
./run_asp.sh up    /path/to/asp_v2.2.2/asp_binary ASP_THERMO_SCAN=up    # RH scanned up 0.20 -> 0.90
./run_asp.sh worst /path/to/asp_v2.2.2/asp_binary ASP_FEE_OUTER=worst   # worst-first electrolyte loop
./run_asp.sh base  /path/to/pre-Claude/asp_binary                       # optional: 34b7ec7 + build/IonReset fixes

# optional: electrolyte-solver diagnostics (dump every solve, replay with coupled and worst-first solvers)
./solver_diag.sh down /path/to/asp_v2.2.2/asp_binary
./solver_diag.sh up  /path/to/asp_v2.2.2/asp_binary up
python3 collect_solver.py

python3 analysis.py                              # work/frac.pkl, work/water.pkl
python3 plot3.py; python3 plot4.py; python3 plot5.py; python3 plot6.py
python3 mkxlsx.py                                # results/ASP_ISORROPIA_ThermoTest_comparison.xlsx
```

The pre-Claude build (`base`) needs the `BinEdges` guard (09afe88), the `IonReset` fix (5b4647e) and the letovicite
output fix from patch 32 to run and report correctly; it still stops at the letovicite composition at 6 of 9
temperatures (negative molality), which the workbook shows as n/a.

## Outputs (`results/`, from the runs of 4 November 2026, ASP asp_v2.2.2 patch 34)

- `ThermoTest_<case>.png`: aerosol fraction (gas fraction on the right axis) and aerosol water vs RH, all temperatures.
- `ThermoTest_<case>_ugm3.png`, `_ugm3_3T.png`: aerosol amounts (µg m⁻³, species on one axis per case), all
  temperatures and 273.15 / 298.15 / 313.15 K.
- `ThermoTest_summary_RH090_vs_T.png`, `ThermoTest_phase_transitions.png`.
- `ASP_ISORROPIA_ThermoTest_comparison.xlsx`: README, Cases, RH0.90, MaxDiff, PhaseRH, Solver, Data, Water, Plots
  (summary sheets are formulas on Data and Water; the wet threshold is an input on README).

The replay dumps are not stored (they are regenerated by `solver_diag.sh` and deleted after each replay).
